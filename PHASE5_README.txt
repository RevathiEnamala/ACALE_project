ACALE PHASE 5 — ADAPTIVE TRANSMISSION OPTIMIZATION
==================================================

Purpose
-------
Phase 5 receives the encrypted packets generated by Phase 4. NORMAL packets
are grouped into batches (default size 5). CRITICAL, EMERGENCY and TAMPERING
packets bypass batching and are sent as immediate singleton batches.

The packet dictionaries are passed through unchanged. Ciphertext, nonce,
authentication tag and AAD are not edited, decrypted or re-encrypted.

Installation
------------
1. Extract this ZIP into the ACALE_Project root folder.
2. Merge the src and tests folders if Windows asks.
3. Keep your existing .env, Phase 4 code and nonce database unchanged.
4. Never share ACALE_MASTER_SECRET.

Run from the project root with .venv activated:
    python run_phase5.py

Optional:
    python run_phase5.py --batch-size 5
    python run_phase5.py --input data/simulation_results/encrypted_sensor_packets.json --output data/simulation_results/transmission_batches.json

Run tests:
    python -m pytest tests/test_transmission_optimizer.py -v

Input:
    data/simulation_results/encrypted_sensor_packets.json

Output:
    data/simulation_results/transmission_batches.json

Urgency detection checks for context_state/state/risk_state/classification in
the packet or visible aad/associated_data/metadata/header. If Phase 4 stores
this label elsewhere or does not expose it, packets default to NORMAL. Check
the Phase 4 envelope structure before relying on urgent bypass.

ENERGY MODEL LIMITATION
-----------------------
The energy estimate is illustrative only, not measured hardware energy.
It uses:
    estimated energy = transmission events * fixed event cost
                       + payload bytes * per-byte cost
It does not model radio hardware, retransmissions, link framing, sleep current
or real device power. Report it as a simulation estimate, not actual measured
energy savings. The prototype does not require physical sensor hardware.
